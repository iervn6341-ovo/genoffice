# Sheets formula cache verification — 2026-10-13

The imported-formula save path had a gap: after changing a precedent, the live engine could show the dependent formula's new result while the saved XLSX retained the original `<v>`. The renderer journal only records edited cells and formulas entered in the current session, so unedited imported formulas were absent from the cache-update request.

Source review confirms the new `residentFormulaValues` path indexes imported formula text, reads the live result only when the model still contains the same formula, and skips formulas owned by content edits. Style-only journal entries remain eligible. It covers fully preloaded workbooks and streamed workbooks with an active bounded dependency closure. The save triggers an automatic calculation pass before harvesting values; manual calculation mode leaves the user's setting in place. A normal save or Save As aborts with a localized retry message if calculation does not apply within the bounded wait, preserving the journal. Background recovery remains best-effort and can retain stale caches if that calculation times out. Formula result types preserve numbers, booleans, strings, and genuine Excel errors. A cached display value over an engine error is not treated as a fresh result.

Independent unit probes cover fresh numeric and boolean results, a genuine `#DIV/0!`, dependent and cross-sheet values, formula-source changes, a content-journaled formula, a style-only journal entry, removed sheets, and preserving a valid cached display value when the raw engine result is `#ERROR!` or another error. The dependency probe also verifies direct and transitive cross-sheet ranges (including quoted sheet names, absolute refs, and case-insensitive sheet-name matching), unrelated edits, cycle termination, a long-chain bound, and a wide range with no content edits. My focused runs passed 70 tests across 6 files before the engine lookup patch, then 24 tests across 3 files after it; these suites overlap. The parent-run final integrated unit suite passed 80 tests across 9 files. The separate loader rerun passed 30 tests across 2 files and overlaps the integrated suite, so counts are not additive.

The parent-run real Electron closure-mode probe passed with 11 imported formulas across four fresh process opens and three saves. It changed precedents, saved once after results appeared, saved again immediately after a second change, then changed only the `Inputs` precedent that makes a cross-sheet formula divide by zero and saved immediately. The final reopen showed all expected live results. Independent ZIP/XML inspection of each saved workbook confirmed every original `<f>` remained and each `<v>` plus formula cell type (`n`, `str`, `b`, `e`) matched the expected fresh result, including the offscreen `M5000` formula. The app now installs a narrow compatibility wrapper at both bundled Univer sheet-name lookup points: the per-unit formula sheet-name map and the workbook's `getSheetBySheetName`. Exact-case matches retain priority, and case-insensitive lookup is the fallback; original formula text is not rewritten. Lowercase `=1/(inputs!A1-40)` Electron probes passed in both closure mode and preloaded mode. Each exercised 11 formulas across four fresh process opens and three saves; the source remained lowercase in the saved XLSX. K1's cache transitioned through `#DIV/0!`, `0.1`, then `#DIV/0!` as its precedent changed, and all other formulas/caches matched expected results. The 50,000 formula-result collection budget matches the current engine-supported bounds: full formula mode is limited to 50,000 grid cells, and an active dependency closure is limited to 50,000 closure cells. Workbooks that cannot activate a closure continue through the sidecar fallback path and are outside this resident-formula harvest. The cached-display fallback now follows edited precedents across direct references, ranges, and indexed formula chains; it short-circuits when the workbook has no content edits. Its dependency walk and range scan are bounded, and an over-budget walk conservatively shows the engine result instead of retaining a potentially stale cache. Native Excel was not tested.
