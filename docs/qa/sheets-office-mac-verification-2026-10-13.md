# Sheets Office Mac verification — 2026-10-13

This is an independent verification of the current Sheets data-validation and header/footer implementation. Native Excel observations remain those documented in the [2026-10-12 details audit](sheets-office-mac-details-audit-2026-10-12.md); this pass did not operate Excel for Mac and does not claim native parity.

## Results

All four unique focused E2E cases passed across two serial built-app runs. The accepted run passed the data-validation list save/reopen and header/footer save/reopen/PDF cases (2 passed, 1.1 minutes); the earlier run passed the folded Home interaction and rejected-list save-error cases. The accepted log and Playwright report are preserved under [`accepted-test.log`](office-mac-evidence-2026-10-13/sheets/accepted-test.log) and [`accepted-html-report`](office-mac-evidence-2026-10-13/sheets/accepted-html-report/index.html). The earlier run, which also contains intermediate failures, is available in [`rerun-html-report`](office-mac-evidence-2026-10-13/sheets/rerun-html-report/index.html).

- **Data Validation:** The UI created a literal list for `B2:B4` containing `  Open  ` and `Closed `. The saved worksheet XML had `sqref="B2:B4"`, `<formula1>"  Open  ,Closed "</formula1>`, and no `<formula2>`. After closing and reopening, the live rule retained the list values and range; reopening the Data Validation panel showed the exact two option values, including their leading and trailing spaces. The authoring UI's `formula2: ","` is per-item default-color metadata; the exporter correctly omits it from the OOXML list rule. The test did **not** open the cell dropdown or choose an item from it.
- **Rejected Data Validation value:** A UI-authored label containing a comma produced an actionable save status directing the user to a cell-range source. The workbook bytes stayed unchanged after the failed save, a second save attempt reported the same error, and the live rule remained available. Unit tests cover the other unrepresentable literal cases and the range/formula-source path; this UI probe exercised the comma case.
- **Header/footer:** The UI saved odd, first-page, and even-page headers/footers, formatting codes, `&F`, `&Z`, and `&A`. OOXML flags and section contents survived close/reopen, and the dialog reopened with the saved texts. PDF text extraction confirmed first-page content and the user workbook filename/path, even-page content and sheet name, then odd-page content on a later page. Disabling first/even variants removed their enable flags while retaining their section XML; reopening and re-enabling restored the original text. The test used a multi-page workbook and verified at least three pages.
- **Folded Home ribbon:** In a separate passing UI run, the test forced a narrow layout, opened the folded Alignment group, selected Orientation → Rotate Text Up from the nested MenuSelect, then opened the font-color palette, selected a swatch, and confirmed the controls closed.

Two product defects were found by the probes and fixed before the accepted run: first, Univer's list-color metadata (`formula2: ","`) was being serialized as a second validation formula and caused the valid UI list save to fail; the gateway now omits list `formula2`. Second, `&F` expanded to the UUID snapshot filename; the main-process open response now overrides the sidecar name using `workbookDisplayName(path, ...)`, and the accepted PDF passed the strict assertion for the user's workbook basename. The helper and its tests cover normal workbooks, recovery targets, CSV imports, and suggested XLSX names. Separate verifier issues were corrected: the raw-quote XML assertion now decodes entities, and the post-reopen check uses the supported rule editor instead of assuming a dropdown DOM selector. These UI/PDF results do not establish Excel's field-expansion behavior.

## Source review and limits

The save error path displays an unwrapped gateway validation message, aborts the staged write, and leaves the journal available for retry. The rejected-value E2E confirms the visible error, unchanged workbook bytes, and retained rule behavior.

For first/even header/footer editing, stored text is supplied to the dialog independently of the enable flags, while print preview still gates those variants by the flags. The E2E disabled-save-reopen-reenable path confirms the intended behavior and verifies the written section XML. Keeping section XML while its enable flag is off is an implementation choice observed here; this test does not establish native Excel semantics for that case.

Known rendering limits remain: non-ASCII font-family names may not preview; Excel double underline `&E` is rendered as single underline; theme/tint `&K` handling is incomplete and may leave text fragments; and page-number offsets such as `&P+/-n` are unsupported. New header/footer image authoring is not available. The actual validation dropdown interaction and all native Excel open/edit behavior remain untested.
