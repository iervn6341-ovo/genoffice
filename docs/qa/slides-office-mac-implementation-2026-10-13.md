# Slides Office Mac detail implementation — 2026-10-13

Scope: Insert → Header and Footer (slide tab behavior). This note records implementation and focused verification. It does not claim full PowerPoint for Mac parity.

## Behavior delivered

- Reopening the dialog reads each slide's saved date field. Fixed text stays fixed; dynamic fields restore their `datetime*` type. The format control exposes `datetime1` through `datetime13` with localized date/time examples based on [Microsoft's field-type mapping](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/209a8afb-4ce6-4ad9-ad6b-f18da263502e). Selecting one updates the cached text and dialog preview immediately. An imported uncommon `datetime*` type keeps its cached value and appears as “Original document format” instead of being normalized to `datetime1` or exposing its raw field type.
- The dialog has separate Apply and Apply to All buttons. Apply sends the current slide index through renderer → IPC → main transaction → pptx-ops registry → pptx-engine. Apply to All omits indexes and targets the deck. The operation validator rejects malformed slide index arrays.
- Existing date, footer, and slide-number shapes are edited in place. Their shape ID, transform, first run formatting, unrelated XML, and animation target survive text and date-mode changes. Additional text runs are cleared; stale later date fields become ordinary runs so a fixed date cannot be misread as dynamic. Effective dialog state reads local placeholders first, then currently rendered layout/master decorations. Turning an item off leaves an empty local placeholder to mask inherited layout/master content on that slide. When a field was visible only through inheritance, Apply current materializes its actual layout/master placeholder before editing or blanking, retaining inherited geometry and first-run style. Referenced hyperlinks/media are remapped from the layout/master relationship file to the destination slide's relationship file; a missing source relationship rejects the edit instead of creating a dangling reference. New placeholders without an active inherited template use fallback geometry and 12 pt gray style.
- Apply to All with “Do not show on title slide” removes local footer-family placeholders on title-layout slides and writes standard `<p:hf dt="0" ftr="0" sldNum="0"/>` toggles into their title layouts. These suppress inherited master footer-family placeholders too. The dialog reads the saved layout toggles on reopen, and when opened on an excluded title slide it echoes the first active content slide's values. Clearing the checkbox removes those three title-layout toggles.
- The dialog preview shows the current slide's date, footer, and slide number, and clears them when title-slide exclusion applies. The current UI has stable test selectors: `hf-date-enabled`, `hf-date-auto`, `hf-date-fixed`, `hf-date-format`, `hf-date-text`, `hf-slide-number`, `hf-footer-enabled`, `hf-footer-text`, `hf-exclude-title`, `hf-preview`, `hf-preview-date`, `hf-preview-footer`, `hf-preview-number`, `hf-apply-current`, and `hf-apply-all`.
- New UI strings were added to all 20 Slides ribbon locales. No new chrome colors or theme tokens were introduced.

## Remaining parity work

- Notes and handout header/footer controls are not shown. The engine stores speaker note bodies, but does not currently model notes/handout header/footer placeholders and their master inheritance as editable settings. A tab without that persistence would misrepresent what save/reopen can do.
- The preview is a simple schematic of the selected slide, not a render of the slide's actual layout and typography. The date/time examples follow Microsoft's documented field type patterns; the exact current PowerPoint for Mac menu wording and locale behavior still need native UI verification.
- An Apply to current slide operation edits that slide's local placeholders. Title-layout exclusion toggles are a deck/layout setting and are written on Apply to All. Imported title layouts with pre-existing `<p:hf>` toggles can be edited by this setting; this is an intentional document-level change.
- A current-slide title exclusion is represented by empty local placeholders that suppress inherited content on that title slide. The checkbox's deck-level checked state is stored only by title-layout `<p:hf>` toggles, so opening the dialog after a current-only exclusion reflects the effective blank slide but does not infer a deck-wide exclusion from that single slide.
- The independent Electron UI probe, native PowerPoint roundtrip, and full app build remain for the lead's scheduled validation wave.
