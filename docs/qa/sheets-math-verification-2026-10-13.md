# Sheets math verification — 2026-10-13

Scope: editable Office equations and font-specific symbol insertion in `apps/sheets`, `packages/office-math`, and `packages/xlsx-gateway`. This is an independent QA pass for the implementation described in `sheets-math-implementation-2026-10-13.md`. It does not claim Microsoft Excel parity without native Excel evidence.

## Source and unit review

- Equation hydration uses the drawing anchor index assigned by the sidecar and recognizes an `a14:m` math shape, including direct `a14:m` shapes from external Office producers. It trusts stored LaTeX metadata only when its SHA-256 digest matches the current OMML and converting that source reproduces the exact OMML. Otherwise it derives source from the current supported OMML. Equations with unsupported math, multiple native math zones, or ambiguous/pictorial fallback text remain read-only.
- Equation save writes native OMML and a text fallback. The equation edit path rewrites only the math payload and matched fallback span, preserving surrounding shape properties, descriptions, and adjacent text; ambiguous fallback content fails closed. Selection, double-click, Enter, F2, and context-menu editing are covered by the renderer path and opt-in UI probe.
- Symbol insertion appends a font-specific rich-text run while retaining the existing document body and run styles. Run positions use JavaScript string offsets (UTF-16), including supplementary-plane symbols. A reopened rich cell may have `getValue() === null`; the insertion path now obtains the authoritative text from `p.body.dataStream` before building the journal value. A regression test covers appending after reopening and checks the original and newly chosen fonts.
- The shared math workbench exposes 42 templates in 11 groups. Its focused renderer tests cover the UI model; those counts do not establish compatibility with Excel’s own equation gallery.

Independent checks run:

## Desktop save/reopen probe

The opt-in test is `e2e/sheets-math-verification.spec.ts`. It creates scratch workbooks only. The equation case inserts a fraction, radical, script, and Greek symbol through the dialog; checks the saved OOXML contains those OMML structures and a matching source digest; reopens the workbook; exercises double-click and F2; edits and saves again; then checks the same visual identity and drawing markers after a second reopen. It also mutates only its scratch workbook with an unsupported native structure and checks that editing is disabled rather than using stale LaTeX.

The symbol case seeds a rich A1 cell with Arial/bold text, inserts Ω using Segoe UI Symbol, saves and reopens, appends ∑ using Cambria Math, and saves/reopens again. It checks both the live cell document and the worksheet XML rich-text runs.

**Accepted final4 desktop run: both E2E cases passed (2/2, 22.5 seconds) against the rebuilt surgical writer.** The equation case inserted a fraction, radical, script, and Ω; saved and reopened them; exercised double-click and F2; edited the source to append `+1`; saved again; and verified the edited source, refreshed digest, stable visual ID and anchor markers, and second reopen. I independently checked the final XLSX ZIP and drawing XML: the edited source is `\frac{\sqrt{x^{2}}}{y}Ω + 1`, its digest matches current OMML, and the shape ID and anchors are unchanged. The second-reopen screenshot visibly renders the added `+1`. The desktop probe inserts and edits GenOffice-authored equations. Preservation of imported transforms, formatting, descriptions, adjacent text, and fallback behavior is covered by focused gateway tests rather than the UI fixture. ## Limits

No native Excel equation editor or symbol insertion workflow was observed in this pass. Direct external `a14:m` import behavior is unit-tested; the desktop probe exercises GenOffice-authored equations. Do not infer that Excel opens, edits, or preserves the authored equations identically from the GenOffice round trip alone.
