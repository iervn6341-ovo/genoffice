# Docs 列印選項評估（對照 Microsoft Word）— 2026-10-16

## 入口分流
- macOS：⌘P、檔案選單、Backstage 的「列印」一律直接叫出 macOS 原生列印面板（含預覽、PDF 選單）。renderer 不開 GenOffice 對話框。
- Windows / Linux：維持內建列印對話框（有預覽），選項依下表補齊。
- 測試覆寫：localStorage `genoffice:docs-force-in-app-print=1` 可在 macOS 強制開內建對話框（僅供自動化測試該對話框）。

資料來源：Word 365（Windows）與 Word 16.x（Mac）的列印頁面一般知識；未貼任何私人文件內容。Mac 版 Word 的「Microsoft Word」附屬面板本次未實機操作（見最後「未驗證」）。

## macOS 原生路徑如何產生 PDF
`printDoc` → `printViaNativePanel`：沿用 `exportPdf`（分頁預覽 `.pv-page` → `printToPDF`，混合紙張時分組輸出再以 pdf-lib 合併，必要時分塊重試）寫入主程序授權的暫存 PDF，再由 `docs:present-native-print` 呼叫 `printPdfWithSystemPanel`。預覽未開時沿用 exportPdf 的延後機制自動開啟再關閉。PDF 與內建預覽一致的依據：兩者讀同一組 `.pv-page`（頁首頁尾、分節紙張、浮動物件、浮水印、頁面邊框都在其中）；分頁預覽位於 `.page-dark` 之外，列印媒體隱藏 `.text-boundary-overlays` 等編輯器疊層，方格線 `.show-grid` 僅作用於編輯器頁面，所以輸出為作者原色。頁面背景色預設不印（等同對話框預設）。取消不報錯；失敗顯示「列印失敗：…」。
